## Install

<InstallTabs />

Check it's on your path:

```bash
s3mirror --version
```

## Describe both endpoints

s3mirror has no useful defaults for the endpoints, so it always needs a config file. Put the source
and destination in `config.yaml`. Anything you leave out takes its default, so this is enough to
start:

```yaml title="config.yaml"
source:
  endpoint_url: "https://s3.source.example.com"
  aws_access_key_id: "SOURCE_ACCESS_KEY"
  aws_secret_access_key: "SOURCE_SECRET_KEY"

destination:
  endpoint_url: "https://s3.destination.example.com"
  aws_access_key_id: "DEST_ACCESS_KEY"
  aws_secret_access_key: "DEST_SECRET_KEY"
```

TLS certificates are checked by default. For an endpoint with a self-signed certificate or one from
a private CA, set `verify_ssl` to the CA bundle's path, as [Safety](/s3mirror/how-it-works/safety/#tls)
shows. The file holds both secret keys: keep it readable only by the account that runs s3mirror, for
example with `chmod 600 config.yaml`.

Print the configuration s3mirror will actually use, with your file merged over the defaults:

```bash
s3mirror --config config.yaml --show-config
```

```json title="Output"
{
  "source": {
    "endpoint_url": "https://s3.source.example.com",
    "aws_access_key_id": "SOURCE_ACCESS_KEY",
    "aws_secret_access_key": "***REDACTED***",
    "region_name": "us-east-1",
    "verify_ssl": true
  },
  "destination": {
    "endpoint_url": "https://s3.destination.example.com",
    "aws_access_key_id": "DEST_ACCESS_KEY",
    "aws_secret_access_key": "***REDACTED***",
    "region_name": "us-east-1",
    "verify_ssl": true
  },
  "performance": {
    "max_workers": 20,
    "multipart_threshold": 8388608,
    "multipart_chunksize": 8388608,
    "max_concurrency": 10,
    "max_pool_connections": 50
  },
  "sync": {
    "delete_extraneous": true,
    "exclude_buckets": []
  }
}
```

Note `"delete_extraneous": true` at the bottom. That's the default, and it means a normal run
deletes destination objects the source doesn't have.

## Run it copy-only

Make the first run copy-only, so nothing at the destination is deleted:

```bash
s3mirror --config config.yaml --no-delete
```

In this example the source has two buckets. The destination already has `app-data`, holding one
matching export, an older copy of `config/settings.json` and a stray `exports/old-report.csv`, and
doesn't have `media-assets` at all:

Add `--debug` to see each decision, such as which objects counted as new and which as changed.
[Logging](/s3mirror/reference/logging/) shows what that looks like.

## Let it delete

When the copy-only run looks right, run it again without `--no-delete`:

```bash
s3mirror --config config.yaml
```

This time nothing needs copying, and the object that exists only at the destination goes:

```text title="Output, the app-data section"
======================================================================
[1/2]: app-data
======================================================================
  Source: 4 objects
  Destination: 5 objects
  Actions: 0 to copy (0.0B), 1 to delete
  ✓ Deleted 1 objects in 0.0s
  ✓ Bucket completed in 0.0s
```

At the normal log level s3mirror only reports how many objects it deleted. Run with `--debug` or
`--log-file` to get each key.

:::caution[Check before the first deleting run]
Deletion is on by default, and it removes anything at the destination that isn't in the source,
including objects someone put there on purpose. Before the first run that's allowed to delete, read
[Deletion](/s3mirror/how-it-works/deletion/), exclude any bucket that only the destination should
have, and keep an independent copy of anything you can't lose.
:::

## Next steps

<Steps>

1. Give s3mirror credentials that can only do what the mirror needs.
   [Safety](/s3mirror/how-it-works/safety/) lists the permissions each side uses.

2. Set the options you care about in the config, such as `exclude_buckets` or a lower
   `max_workers`. [Configuration](/s3mirror/guides/configuration/) walks through the file.

3. Schedule it with `--log-file`, and alert when it exits with anything other than 0.
   [Scheduling](/s3mirror/guides/scheduling/) has cron and systemd examples.

</Steps>
