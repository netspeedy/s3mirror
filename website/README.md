# s3mirror website

This folder is the source of the s3mirror documentation site,
<https://netspeedy.github.io/s3mirror/>, built with Astro and Starlight. The pages are
Markdown and MDX in `src/content/docs`, and some of them use components that only
render on the site, so read the docs there rather than here.

The components and styles are the same in every netspeedy docs site and use the
`ns-` prefix; s3ctl's site is the standard they follow, so copy changes to them
from there rather than editing them here. What's particular to s3mirror, such as
its name, description, links and footer columns, is in `src/lib/site.ts`. The
sidebar groups, their colours and icons, and which header tab shows which group
are defined in `src/lib/sections.ts` and matched to the sidebar in
`astro.config.mjs` by label. The other files written for s3mirror are the pages,
`src/components/HomeTop.astro`, `src/components/InstallTabs.astro`,
`src/pages/404.astro` and the palette at the top of `src/styles/theme.css`.

## Working on it

Run these from the repository root:

```bash
make website-install   # npm ci, from package-lock.json
make website-dev       # local server with live reload
make website-build     # production build into website/dist/
make website-check     # every page, the search index, icons, share card and internal links
make website-test      # theme, header, tabs, version menu and an archived line in headless Chrome
make website-capture   # desktop and phone screenshots in both themes into website/.captures/
```

`make website-check` reads `website/dist`, so it always runs after the build. `make
website-test` builds its own copies into `website/.test/`. The first test or capture
run downloads the Chrome build Puppeteer pins. CI builds with the newest Node 22
release (`check-latest` in setup-node), since the version a runner has cached can be
older than Astro's minimum, which is in `engines` in `package.json`.

`public/og-image.png`, `public/og-image.svg`, the favicons, the Apple touch icon and
`src/assets/mark.svg` are generated by `make readme-hero` along with the README
banner, so edit `scripts/readme/build_readme_hero.py` rather than the files.

`tests/test_docs.py` fails when an option is added to or removed from s3mirror's
parser without updating `src/content/docs/reference/cli.mdx`.

## Versions

The shared components can serve older release lines beside the latest, but
s3mirror doesn't publish archived lines, so the version menu in the header lists
only the current release. Every page describes the latest release.

## How it's published

Deploy Pages Site runs on every push to `main`, when a release is published by
hand, and after each GitHub Release run. That last trigger is what puts a new
version on the site: GitHub Release creates releases with `GITHUB_TOKEN`, which
doesn't start release-event workflows. It can also be started by hand. It writes
the latest release's tag and URL to a JSON file, passes it to the build in
`SITE_METADATA_FILE`, runs `make website-check` over the result and deploys it. Dependabot checks the npm
dependencies here weekly and titles its pull requests `chore:`, so a site update
doesn't cut a release.
